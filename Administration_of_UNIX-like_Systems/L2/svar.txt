1.vmstat visar

PROCESSES:
r - antalet processer som körs eller väntar på CPU
b - blockerade processer som väntar på I/O (t.ex disk eller nätverk), dessa processer använder inte CPU, men väntar på resurser.

MEMORY:
swpd - antalet kB som används i swap (virtuellt minne på disk). Om detta är > 0 betyder det att systemet har bytt ut minne från RAM till disk.
free - Antalet kB ledig RAM. 
buff - Minnet som används för buffer (tillfälligt lagringsminne för blockenheter, t.ex disk).
cache - Minnet som används för filcache. Linux håller ofta filer i minnet för snabb åtkomst, även om de tekniskt sett kan frigöras vid behov.

SWAP:
Swap används när RAM är fullt
si/swap in - Antalet kB som lästs från swap tillbaka till RAM/sek, om > 0 betyder det att systemet måste läsa minne från disken.
so/swap out - Antalet kB som skriv från RAM till swap/sek, om > 0 betyder det att systemet har för lite RAM och flyttar minne till disk

IO:
bi/blocks in - Antal block som lästs från blockenheter/sek. (Högt värde = mycket läsning från disk)
bo/blocks out - Antal blocks som skrivits till blockenheter/sek. (Hög värde = mycket skrivning till disk).


SYSTEM
in - Antal interrupts per sekund
cs - Antal context switches per sekund

CPU:
us - % CPU-tid som använts av användarprocesser
sy - % CPU-tid som använts av kärnprocesser
id - % IDLE, alltså CPU-tid som tid som är ledig
wa - % WAIT CPU-tid som väntar på I/O
st - %STEAL CPU-tid stulen av hypervisor i virtualiserad miljö

2.top visar: 
PID - processens unika ID
USER - Användaren som startade processen.
PR - Prioritetsnivå
NI - Snällhetsgrad
VIRT - virtuellt minne, allt minne processen kan använda, inkl delat, swap, reserverat.
RES - Faktiskt minne i RAM just nu
SHR - Delat minne med andra processer. 
S - Processens tillstånd
%CPU - hur mycket CPU tid processen använder
%MEM - hur mycket minne processen använder
time+ - Visar hur mycket CPU tid processen har förbrukat sedan start av system.
COMMAND - Namnet på processen.

DEL 4

Alla operativsystem har ett eget set av diagonistiska filer för att spåra aktivitet och errors. De mest användbara metoderna när det gäller rapporter och eventloggar i linux är /var/log/messages* filerna eller /usr/dmesg kommandot.
Om ett program avslutas onormalt, till exempel pga otillåten minnesåtkomst(SIGSEGV), en ogiltig instruktion, buss-error osv... skapar systemet en core-fil. Denna fil innehåller en minnesdump av processen vid det ögonblick då processen krachade. Syftet med core-filen är att ge utvecklare möjlighet att felsöka problemet i efterhand, eftersom den bevarar programmets minnesinnehåll, stack och registervärden vid krachen. 

1.
Det kommandot kan ibland också kallas för "driver message" , visar meddelanden dirket från linux-kärnan. Det är framför allt info från drivrutiner och systemstarten. Hårdvara som hittas, moduler som laddas, och dmesg låter utvecklare läsa dem i efterhand.

Syslog är en dagbo där tjänster, program och delar av operativsysstemet skriver sina loggar. Det är textfiler under /var/log och där hittar man allt från nätverksproblem till autentisering, pakethantering och egna meddelanden man skickar med logger. Syslog fångar alltså systemets allmänna aktivitet.
Syslog visar information från hela systemet, kernel, system, applikationer osv. 

dmesg visar det som själva kärnan skriver om hårdvara och drivrutiner. Detn är kernel ring buffer: när systemet startar, när en usb-enhet kopplas in, när ett nätverkskort beter sig underligt. Det är rått och närmare maskinens hårda metall. dmesg används då främst för att felsöka uppstart och hårdvarufel. 
dmesg visar kernel buffer, endast kernel och drivrutinsmeddelanden.
